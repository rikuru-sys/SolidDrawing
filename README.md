# 立体ドローイング

3Dで生成された立体を観察し、制限時間内に描くためのWebアプリケーションです。  
短時間の反復練習から、描画後の比較・振り返りまでをブラウザ上で完結できます。

[公開デモを試す](https://rikuru-sys.github.io/SolidDrawing/)

最新バージョン：`0.1.0`

![立体ドローイングのプレビュー](./public/og.png)

## このアプリについて

立体を描く練習では、毎回異なる見本を用意する手間や、描いた結果を客観的に振り返りにくいという課題があります。

このアプリでは、立体・向き・比率・光源をその場で生成し、見本の観察、描画、比較、保存、同じ条件での再練習までを一つの流れとして提供します。

## 担当範囲とAIの利用方針

AIを活用して実装し、その後もリファクタリング、コードレビュー、不具合修正、テスト追加を進めている個人開発プロジェクトです。AIの利用範囲には、初期コードの生成だけでなく、原因調査、修正案の作成、検証コマンドの実行、ドキュメント作成も含みます。

今回の品質改善では、次のように役割を分担しました。

| 担当 | 実施した内容 |
| --- | --- |
| 開発者 | 全体レビューを依頼し、指摘された不具合の修正と日本語名のE2Eテスト追加を依頼。公開前の確認、バージョン0.1.0への更新、コミット・プッシュを指示 |
| AIアシスタント | コードの調査、不具合の再現、原因分析、修正とテストの実装、検証の実行、ドキュメント整備、指示に基づくコミット・プッシュ |

成果を説明する際は、開発者が行った判断とAIが実行した作業を区別します。AIの提案や説明は、関連する実装・再現条件・テスト結果と結び付けて記録し、未検証の環境や機能も明記する方針です。

## 不具合修正と検証の事例

コードレビューで見つかった4件の不具合に対し、日本語名のE2Eテストを9件追加しました。

| 課題 | 修正内容 |
| --- | --- |
| 線が画面に残っているのに、消しゴム使用後の評価では描画なしになる | 描画Canvasの表示サイズを評価処理へ渡し、座標と線幅を同じ倍率で変換 |
| 複数タッチで最初の線が消え、別の指へ線がつながる | 描画開始時のポインターIDを保持し、それ以外の指による開始・移動・終了を除外 |
| 一時停止を繰り返すと、1秒未満の描画時間が失われる | 内部の経過時間をミリ秒で保持し、表示・記録時に秒へ変換 |
| 見本の読み込みに失敗しても、時間切れで空の結果が保存される | 現在の見本と評価用Canvasの準備状態を、計時・描画入力・保存処理へ連携 |

最新の確認では、E2Eテスト41件、ユニットテスト211件、型チェック、Lint、GitHub Pages用ビルドの成功を確認しました。これは現在の自動検証範囲の記録であり、すべての端末での動作を保証するものではありません。

[修正事例の詳細](./docs/IMPROVEMENTS.md)には、再現条件、原因、対応、テスト項目と残っている検証範囲をまとめています。

## 主な機能

- 立方体、直方体、円柱、楕円柱、三角錐、円錐の3D見本を生成
- 10〜60秒または時間制限なし、最大20回までの連続練習
- 簡単・難しいの2段階で立体の向きを調整
- 輪郭線と薄い陰影、輪郭線と影、見えない部分を点線で示す表示に対応
- 見本と描画スペースの上下・左右配置を変更
- 見本を途中で隠すモード、見本だけを表示するモード
- ペン、点線、補助線、消しゴムと、「輪郭線と影」で使用できる専用の影ペン
- 太さ・手振れ補正と、通常線の色・透明度を練習中にも変更可能
- 元に戻す、やり直す、全消去に対応
- 描画後に見本との横並び比較・中心を合わせた重ね合わせ比較を表示
- 輪郭、線の傾き、大きさ、比率と、影表示時の投影影を使った自動評価
- 見本、描画、比較画像、全結果をPNG形式で保存
- 気になる見本をお気に入りに保存し、同じ条件で再練習
- 設定とお気に入りを、保存形式のバージョンとともにブラウザ内へ保存
- 3D見本を読み込めない場合のエラー表示と再試行
- 画像作成中の操作抑止と、保存結果・エラーの表示

## 技術的なポイント

### 再現可能な3D見本生成

Three.jsで立体を描画し、形状、比率、カメラ、物体の回転、光源をプロンプトデータとして管理しています。乱数生成をシード値から分離しているため、通常はランダムに出題しながら、テストでは生成条件を固定でき、お気に入りでは保存済みの見本をそのまま再現できます。

### 拡張しやすい描画ツール

描画ツールごとに線の太さ、透明度、破線、評価時の扱いを定義し、ツールレジストリから利用する構成にしています。影ペンは通常線とは別の評価役割を持ち、固定の薄いグレーと広い筆幅で投影影を描きます。透明度に頼らず影を識別するため、通常ペンの薄い線を誤って影として扱いません。新しいペンを追加するときに、描画処理全体へ変更が広がりにくい設計です。

### CanvasとSVGの使い分け

練習中の入力にはCanvasを使用し、結果画面と画像出力にはストロークデータから生成したSVGも利用しています。画面サイズが変わっても線を滑らかに表示でき、見本との比較や保存にも同じ描画データを再利用できます。

### 画面と処理の責務分離

`app/page.tsx`は画面遷移と機能間の接続に絞り、練習セッション、試行結果生成、結果画面内の比較状態、LocalStorageの読み書きを機能別に分離しています。各処理の利用範囲を狭くすることで、変更箇所を追いやすく、ブラウザ機能を差し替えたテストを書きやすい構成にしています。

### 位置に左右されにくい形状・影評価

見本と描画の中心を合わせてから、輪郭、線の傾き、大きさ、縦横比を評価します。傾きは形の中を3×3に分け、同じ位置にある線の方向を比較するため、画像全体に同じ種類の斜線や縦線が含まれるだけでは高得点になりません。「輪郭線と影」では、完成見本とは別に形状だけ・投影影だけの評価用画像を生成し、同じ中心合わせを影にも適用します。これにより、立体に対する影の方向・位置・広がりを独立した項目として評価します。描いた位置そのものではなく、形・大きさ・相対的な位置関係を振り返るための補助指標です。

### 画面サイズへの対応

デスクトップ、タブレット、液晶ペンタブレットでの利用を想定し、横長画面や高さの低い画面では、練習に必要な操作を一画面内に収めるレスポンシブ調整を行っています。

## ローカルでの実行方法

Node.js 22.13以上が必要です。

```bash
git clone https://github.com/rikuru-sys/SolidDrawing.git
cd SolidDrawing
npm ci
npm run dev
```

表示されたローカルURLをブラウザで開いてください。

## 検証

```bash
# ユニットテスト
npm test

# Chromiumによる主要操作のE2Eテスト
npm run test:e2e

# 型チェック
npm run typecheck

# 静的解析
npm run lint

# GitHub Pages用ビルド
npm run build:pages
```

乱数、出題生成、設定保存、タイマー、描画履歴、SVG生成、自動評価、お気に入り、3D見本のエラー表示、画像保存中の状態などをVitestで確認しています。Playwrightでは、描画から結果表示、時間制限、一時停止、見本のみ、お気に入り、画像保存に加え、デスクトップ・横長・縦長画面の共通表示条件をChromiumで確認します。自動評価では6種類の立体と3種類の見本表示の組み合わせに加え、通常線と影線の分離、影の中心合わせ、形状・影の配点を固定データで確認しています。

## データの取り扱い

設定とお気に入りは利用端末のLocalStorageへ保存形式のバージョン付きで保存し、既存の旧形式も読み込めるようにしています。個人情報の入力や外部サーバーへの送信を必要としない、静的なWebアプリケーションです。

## 対応環境

最新版のChromium系ブラウザを自動テストの対象としています。マウス操作と、CDPで再現した複数タッチをE2Eテストで確認しています。実機のタッチ・液晶ペン入力は手動確認対象であり、今回の自動検証には含めていません。Firefox、Safari、古いブラウザの動作は現時点では保証していません。
