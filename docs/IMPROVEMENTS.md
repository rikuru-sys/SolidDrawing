# 不具合修正と回帰テストの事例

バージョン0.1.0の品質改善として対応した4件の不具合をまとめます。修正は[コミット47e83f6](https://github.com/rikuru-sys/SolidDrawing/commit/47e83f6)に含まれます。

開発者が全体レビューと不具合修正、日本語名のE2Eテスト追加を依頼し、AIアシスタントが調査・再現・修正・テスト実装・検証を実行しました。以下はその作業記録であり、開発者が単独で発見・実装した事例としては扱いません。

## 1. 消しゴムの見た目と評価結果の不一致

### 現象と再現条件

幅584 CSSピクセルの描画Canvasに縦線を引き、その少し横を消しゴムでなぞると、画面には線が残っているのに「評価できる主線が少ない」と判定されました。

### 原因

評価処理は描画を180×180ピクセルの画像へ変換します。ストロークの座標はこの画像に合わせて変換していましたが、消しゴムの幅は表示時のピクセル値のままでした。そのため、評価画像では消しゴムが相対的に大きくなり、画面では消していない線まで消去していました。

### 対応

結果生成時に描画Canvasの表示サイズを取得して評価処理へ渡します。ストロークを表示時の座標へ戻し、Canvasの変換行列で座標と線幅をまとめて解析用サイズへ変換するようにしました。形状と影の評価に同じ変換を適用します。

### 検証

次の2項目で、消去前後のCanvasの可視画素数と結果画面の評価メッセージを確認します。

- 線の横を消しても残っている線を評価できる
- 線を直接消すと評価対象からも消える

関連ファイル：[評価処理](../src/features/evaluation/shape-evaluator.ts)、[結果生成](../src/features/results/attempt-capture.ts)、[E2Eテスト](../e2e/drawing-regressions.spec.ts)

## 2. 複数タッチによる線の消失と混線

### 現象と再現条件

1本目の指で描画している途中に2本目の指で触れると、最初のストロークが失われたり、指の間に意図しない線が引かれたりしました。

### 原因

入力中のストロークは1つだけ保持していましたが、新しいタッチの開始を制限していませんでした。移動・終了イベントもポインターIDを照合していないため、異なる指のイベントが同じストロークへ作用していました。

### 対応

描画中は別のポインターによる開始を受け付けず、移動・終了時も描画開始時のポインターIDと一致するイベントだけを処理します。複数の指による同時描画を追加するのではなく、1本の線を確実に追跡する仕様にしました。

### 検証

「描画中に別の指で触れて離しても最初の指の線だけを保存する」を追加しました。Chromium DevTools Protocol（CDP）で2点のタッチを発生させ、2本目の指を動かして離した後も1本目の描画が続くことを確認します。保存されたSVGのパス数・横座標・始点・終点を検査し、線の消失と混線を検出します。

関連ファイル：[入力処理](../src/features/drawing/use-drawing-pointer.ts)、[E2Eテスト](../e2e/drawing-regressions.spec.ts)

## 3. 一時停止による端数時間の消失

### 現象と再現条件

修正前は、10秒設定で「550ミリ秒進めて一時停止・再開」を20回繰り返すと、実動11秒後も残り10秒と表示されました。時間制限なしの場合も、一時停止前の端数が経過時間に蓄積されませんでした。

### 原因

再開時に、秒単位へ丸めた残り時間や経過時間を使って計時を再構成していました。各区間の1秒未満の時間が失われるため、一時停止の回数に応じて誤差が増えていました。

### 対応

累積時間と現在の計時開始時刻をミリ秒単位で保持し、一時停止時に端数を含めて累積します。秒への変換は画面表示と結果記録の時点で行います。また、次問へのリセット後に前問の終了処理が時間を上書きしないよう、計時の世代を識別します。

### 検証

次の3項目を追加しました。端数を扱うテストではPlaywrightの時計を停止し、指定した時間だけ進めることで操作速度による誤差を除いています。

- 短い描画と一時停止を繰り返しても実際の制限時間で終了する
- 時間制限なしでも一時停止前の端数を経過時間と保存時間へ加算する
- 連続練習では前問の経過時間を引き継がず各問に制限時間を確保する

関連ファイル：[タイマー](../src/features/practice/use-practice-timer.ts)、[E2Eテスト](../e2e/timer.spec.ts)

## 4. 見本の読み込み失敗中に空の結果を保存

### 現象と再現条件

3D見本のJavaScriptチャンクへの通信を失敗させると、エラーが表示されてもタイマーは進み、10秒後に空の見本で結果画面へ移動していました。

### 原因

計時は練習画面の表示を条件に開始していました。終了処理はCanvas要素の存在を確認していましたが、現在の問題の見本が正常に描画されたかは確認していませんでした。

### 対応

描画結果を現在の描画要求にひも付け、前の問題や再試行前の状態を準備完了として扱わないようにしました。影モードでは表示用・形状評価用・影評価用のCanvasすべての準備を待ちます。この状態を計時・描画入力・保存処理へ渡し、準備ができるまで時間を進めず、空の見本で結果を保存しないようにしました。

### 検証

次の3項目を追加しました。通信失敗と一時的なWebGL描画失敗は別々に発生させています。

- 見本の読み込みに失敗した場合は時間切れや終了操作で空の結果を保存しない
- 見本が未準備の間は時間制限なしでも手動保存を無効にする
- 見本の描画失敗から再試行で復旧すると制限時間を最初から使える

復旧テストでは影モードを使用し、再試行後に準備が完了してから設定どおりの時間を使えることを確認します。通信に失敗した動的インポート自体の再読み込み成功は、このテストの確認対象には含めていません。

関連ファイル：[見本の描画状態](../src/features/sample/use-sample-canvas.ts)、[練習用Canvasの連携](../src/features/practice/use-practice-sample-canvases.ts)、[保存処理](../src/features/practice/use-attempt-finisher.ts)、[E2Eテスト](../e2e/sample-loading.spec.ts)

既存の通常操作のE2Eテスト32件は、修正前にも成功していました。今回の事例では、複数ポインター、1秒未満の停止・再開、表示と評価の座標変換、非同期の描画失敗という条件を追加することで、通常操作だけでは検出できなかった不具合を回帰テストへ残しました。

自動検証はChromiumが対象です。CDPでのタッチ入力は実機のタッチ・ペン入力の確認を代替するものではありません。Safari・Firefox、3D見本全体の画像差分、評価点と人による描画評価の一致度は今回の検証対象外です。現在のテスト方針と実行方法は[TESTING.md](./TESTING.md)を参照してください。
