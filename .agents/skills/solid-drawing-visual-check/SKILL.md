# 画面と保存画像の確認

画面を表示し、必要に応じてPNGを保存・展開して、利用者が見る結果を確認する。コードやファイル名の検査だけで「見た目も正常」と判断しない。

## 範囲と実行環境

- ユーザーが指定した画面・不具合・出力形式を最優先する。「確認だけ」の依頼ではアプリを修正せず、問題と再現条件を報告する。「修正して」の場合は再現、修正、同条件での再確認を行う。どちらも公開やバージョン変更は自動で行わない。
- リポジトリの`package.json`、`playwright.config.ts`、関連する`e2e/`と`docs/TESTING.md`を確認する。既存のPlaywrightとブラウザ操作ツールを使い、追加のブラウザ製品・ライブラリ導入は必要な場合だけ行う。
- ローカル確認を基本とする。ビルド済みの静的サイトであれば既存のテストサーバーを使う。現行のパスは`http://127.0.0.1:4173/SolidDrawing/`だが、設定と起動ログで確認する。古いビルドを見ないよう、変更後の成果物か確認する。
- 既存のユーザー用ブラウザとは別のテストコンテキストを使う。`e2e/fixtures/app-fixture.ts`の`AppDriver.open()`はLocalStorageを消去するため、利用者のお気に入りがあるセッションで実行しない。
- 表示待ちは見本の準備状態、画像の読み込み、フォントの読み込みなどで判定する。固定の待ち時間だけで読み込み成功としない。乱数の影響がある比較は同じ出題条件・シードを使う。
- 起動したサーバー・ブラウザだけを終了する。確認できない環境は未確認と記載し、成功を推測しない。

## 確認条件を選ぶ

全条件の組み合わせを毎回実行しない。まず報告された条件を再現し、変更の影響が及ぶ境界条件を追加する。

| 対象 | 代表条件 |
| --- | --- |
| 結果画面 | 横長1440×900、高さの低い1280×551、縦長390×844。幅の境界に関係する修正は該当CSSの境界前後も確認 |
| 結果一覧 | 1問と10問、先頭・途中・末尾の選択、長い立体名、秒数と評価、見本のみモード |
| 通常の一括PNG | 見本・描画・見本・描画の4列、1行2問。1・2・3問で行の境界、10問で5行 |
| 重ね合わせの一括PNG | 中心合わせ画像を4列、1行4問。1・4・5問で行の境界、10問で3行 |
| 評価欄 | 通常評価と影評価。影項目が増えても文字が収まること |

単独の比較画像は一括PNGと別の仕様。出力寸法・行数は`src/features/results/result-image-composer.ts`と最新の要求に照らす。将来仕様が変わった場合は、この表も更新する。

## 画面で確認すること

1. 指定の画面サイズ・設定・結果数で対象画面へ進む。操作手順、表示サイズ、選択中の問番号を記録する。
2. 対象要素をスクリーンショットで確認し、必要に応じて要素の矩形・スクロール寸法を測る。文字の下端、枠、画像の輪郭、保存ボタン、スクロールの末尾を確認する。
3. 結果一覧の秒数・評価が各ボタン内に収まり、隣の項目に重ならないことを確認する。長い一覧は項目の高さを潰さずスクロールできることを確認する。
4. 見本・描画が意図せず切れていないか、下部に過剰な空白がないかを確認する。モバイルの縦並びや必要な縦スクロールを不具合扱いしない。
5. 再現できた不具合を修正する場合は、修正前後を同じ条件で比較する。隣接する画面サイズ・モードを必要な範囲で確認する。

## 保存PNGで確認すること

1. 実際の保存ボタンからダウンロードし、一括通常・一括重ね合わせを取り違えない。`e2e/downloads.spec.ts`の既存テストは保存成功とファイル名が中心で、PNGの見た目を保証しない。
2. 保存したPNGを画像表示ツールで開く。全体で列数・行数・問番号の順序を確認し、原寸または文字が読める拡大率でも確認する。縮小画像だけで文字の見切れを判定しない。
3. 通常出力は各問の見本と描画が隣り合うこと、重ね合わせ出力は両方の画像が存在し設定した不透明度・中心合わせが反映されることを確認する。見本と区別できる既知の描画を入力する。
4. 総問題数と出力された問番号が一致し、最後の不完全な行で問題が欠落・重複しないことを確認する。余ったセルは許容するが、不要な行は許容しない。
5. 見本・描画・影の欠け、縦横比、見出し、秒数、各評価、全体の集計欄を確認する。合計や平均の確認が必要な場合は入力結果と照合する。
6. 画像全体が白紙でないことだけでは十分でない。番号ごとのセルに正しい画像があるか、文字が隣のカードにはみ出していないかを見る。

## 証拠と報告

- 証拠は`outputs/visual-check/`などGit管理対象外の作業フォルダーへ保存する。機密・個人データを含まないテスト結果を使う。
- 報告には「確認対象・画面サイズまたは問題数・期待結果・実際の結果・証拠ファイル」を含める。確認済みと未確認を区別し、ブラウザ名と版を記録する。
- 画面とPNGを両方確認した場合は結果を分けて記載する。一方しか見ていなければ、その範囲だけを報告する。
- 画像差分を自動テストにする場合は描画条件を固定し、フォント・アンチエイリアス等による差を考慮する。実装に合わせて期待画像を無条件更新しない。
- 再発防止の自動テストは実際の不具合を検出するものを選ぶ。今回の確認に不要な全画面スナップショットや大量の重複テストを追加しない。

## 呼び出し例

- 「結果一覧の秒数がはみ出すので、再現して修正して」：報告条件で再現し、修正後も同じ表示を確認する。
- 「画面と保存PNGを確認して。修正・公開はしないで」：分離したテスト環境で確認し、証拠と問題点だけ報告する。
- 「10問分の重ね合わせPNGが4列になっているか確認して」：実際に保存したPNGで4列・3行・10問の欠落なしを確認する。
